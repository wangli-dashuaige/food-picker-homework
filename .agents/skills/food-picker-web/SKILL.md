# food-picker-web

用于本项目（「今天吃什么随机选择器」）以及同类**极简网页小工具**的开发、修改与检查。

## 何时使用

- 用户要求新建 / 修改一个只用 HTML、CSS、原生 JavaScript 的页面。
- 需要给页面加按钮、输入框、列表、随机抽取、增删条目等基础交互。
- 改完代码后，需要检查按钮、输入框、空输入、空列表这些容易出问题的场景。
- 需要写或更新本项目的 `README.md`，说明怎么运行。

## 项目现状（改动前必须确认）

```
项目根目录/
├── index.html   # 全部页面结构、样式、脚本（单文件）
├── README.md    # 功能说明与运行方法
├── AGENTS.md    # 项目开发规则（优先遵守）
└── .agents/skills/food-picker-web/SKILL.md   # 本 Skill
```

`index.html` 的关键结构（改动时保持这些 id 可用）：

| 元素 | id / 类名 | 作用 |
| --- | --- | --- |
| 随机按钮 | `#pickBtn` | 「帮我决定」，抽一种食物 |
| 结果文字 | `#resultFood` / `#resultEmoji` | 醒目展示抽取结果 |
| 输入框 | `#foodInput` | 输入新食物 |
| 添加按钮 | `#addBtn`（在 `#addForm` 内） | 提交添加，回车同样生效 |
| 提示行 | `#hint` | 成功 / 警告反馈 |
| 食物列表 | `#foodList`，每项 `.food`，删除按钮 `.food__del` | 增删条目 |
| 空清单提示 | `#emptyTip` | 列表为空时的占位文案 |

## 工作流程

### 1. 先检查项目文件

动手前先读，不要凭印象改：

1. `AGENTS.md`：项目硬性规则（技术边界、功能规则、自检清单）。
2. `index.html`：当前页面结构、`<style>`、`<script>`，并**列出已实现的功能**。
3. `README.md`：对外承诺的功能与运行方式。
4. 用 `Get-ChildItem` 看目录里有没有多余文件或用户新放的素材。

### 2. 明确用户需要的网页功能

用一两句话复述需求，写清「改哪个文件、动哪个函数、用户会看到什么变化」。
需求含糊时先问，不要猜着改。判断标准：用户能在页面上点到什么、看到什么。

### 3. 实现（原生优先）

- 只用 HTML、CSS、原生 JavaScript；不引入框架、构建工具、CDN 资源。
- 默认全部写进单个 `index.html`：样式放 `<style>`，脚本放 `<script>`。
- 不调用外部 API、不读写数据库、不加 `localStorage`。
- 新功能是「加法」：**不擅自删除已有功能**，保留默认 8 种食物、抽取、添加、删除等能力。

### 4. 写代码的约定（适合初学者）

- 脚本用 `"use strict"` 的 IIFE 包裹，DOM 引用集中在 `els` 对象里。
- 状态只有 `foods`、`idSeed`、`currentFood` 几个变量，不引入额外全局状态。
- 用户输入一律用 `textContent` 插入 DOM，不拼 `innerHTML`。
- 函数短小单一职责：`render()` 画清单、`pickFood()` 抽取、`addFood()` / `removeFood()` 增删。
- 中文注释写「为什么」，命名用小驼峰，缩进 2 空格或 4 空格保持全文件一致。
- 新增 UI 复用 `:root` 里的颜色 / 圆角变量，不硬编码新色值。

### 5. 改完必查

**按钮与输入框**

- [ ] `#pickBtn`：能出结果，且结果属于当前清单；连点多次结果会变。
- [ ] `#addBtn`：正常输入能添加，输入框清空，数量角标同步。
- [ ] 回车键：在输入框按回车同样能添加。
- [ ] `.food__del`：每个条目都能单独删除，删完列表正确收缩。
- [ ] 新加的任何按钮 / 链接都有事件绑定，且没有指向空函数。

**异常情况**

- [ ] 输入为空 → 不添加、有文字提示、有视觉反馈（如抖动）。
- [ ] 只输入空格 → 同样不添加。
- [ ] 列表为空时点抽取 → 只提示「先添加食物」，**不抛异常**。
- [ ] 删除的正是当前结果 → 结果区回到引导文案，不显示已不存在的食物。
- [ ] 重复添加同名食物 → 被拦截并提示。
- [ ] 浏览器 F12 控制台无红色报错。

**回归**

- [ ] 页面标题仍是「今天吃什么？」。
- [ ] 首次打开仍是 8 种默认食物、角标「8 种」。
- [ ] 布局在 1000px 左右宽度下不错位、按钮好点。

### 6. 完成后总结

回复中必须包含三部分：

1. **改了什么**：逐个文件说明改动内容（只列真实改动的文件）。
2. **怎么验证的**：说明实际执行过的检查。
   - 实际在浏览器里点过按钮 → 写清点了哪些、结果如何。
   - 只做了代码阅读或 `node --check` → 写「仅静态检查，未实际运行」。
   - **没有跑过的测试，绝不能声称通过**，也不要编造测试数量或截图。
3. **怎么运行**：双击 `index.html`，或用 `python -m http.server 8000` 后访问 `http://localhost:8000`。

## 常见改动配方

- **加一个食物**：改 `DEFAULT_FOODS` 数组即可；同名 Emoji 记得补进 `EMOJI_MAP`，否则走兜底图案。
- **加自定义 Emoji**：在 `EMOJI_MAP` 里加一条 `"食物名": "🍤"`。
- **换配色**：只改 `:root` 里的 `--primary`、`--bg`、`--primary-soft`，不要逐处改色值。
- **加新交互区**：在两张 `.card` 之后追加一张卡片，样式复用 `.card` / `.btn`，事件绑在初始化区末尾。
- **改文案**：中文语气保持轻松口语化，与现有文案统一。

## 禁止事项

- 不引入 React / Vue / jQuery / Tailwind 等任何框架或 CSS 库。
- 不要求用户 `npm install`、打包或编译。
- 不调用外部 API、不写数据库、不加载外部字体或图片。
- 不为了「看起来专业」拆分文件、加构建工具或加过度抽象。
- 不删除或改坏已经实现且用户可见的功能。
